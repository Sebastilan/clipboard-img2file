## Context



监控进程莫名其妙挂了，但计划任务的 RestartOnFailure 没有生效。



**根因**：`install.bat` 第 50 行用 `Start-Process` 直接启动监控，绕过了 Task Scheduler。计划任务配的是 `AtLogOn` 触发器，安装后用户没重新登录，所以任务从未触发过。Task Scheduler 只能重启它自己启动的进程——手动启动的进程挂了，它根本不知道。



此外，进程被强杀时没有任何诊断信息（连 finally 都没执行），下次再发生无法定位原因。



## 改动方案



### 1. install.bat — 通过 Task Scheduler 启动（而非 Start-Process）



**文件**: `install.bat`



- **第 50 行**：`Start-Process powershell.exe ...` → `Start-ScheduledTask -TaskName $appName`

- 这样 Task Scheduler 拥有进程的生命周期，RestartOnFailure 才能生效

- 验证逻辑不变（检查进程是否在运行）



### 2. install.bat — 提高 RestartCount



**文件**: `install.bat` 第 45 行



- `RestartCount 3` → `RestartCount 999`

- 避免连续崩溃 3 次后就放弃重启



### 3. clipboard-img2file.ps1 — 添加崩溃诊断



**文件**: `clipboard-img2file.ps1`



在 `try` 块之前（约 214 行），添加：



a) **心跳日志**：主循环中每 5 分钟写一条 heartbeat，附带内存用量和运行时长

   - 进程死了可以从日志精确到 5 分钟窗口

   - 内存持续增长 → 内存泄漏 → OOM kill



b) **AppDomain.UnhandledException 处理器**：捕获绕过 try/catch 的 .NET 底层崩溃，写入日志



c) **PowerShell.Exiting 事件**：进程正常退出时记录原因



d) 在 `finally` 块中增加退出码记录



### 4. 立即修复当前环境



改完代码后：

- 复制新脚本到安装目录 `%LOCALAPPDATA%\clipboard-img2file\`

- 停掉当前手动启动的进程
